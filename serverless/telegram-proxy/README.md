# Прокси лид-формы → Telegram

Заявки с сайта уходят не напрямую в Telegram Bot API, а через этот Cloudflare Worker.
Токен бота и chat_id хранятся секретами воркера, поэтому их **нет в коде сайта** и их
нельзя вытащить из «Просмотра кода страницы».

## Почему так

Раньше токен бота лежал прямо в `js/app.js`. Любой мог открыть исходник, забрать токен
и захватить бота (спам, удаление сообщений, чтение чата, фейковые заявки). Теперь
фронтенд отправляет на воркер только текст заявки — токен добавляет уже воркер на сервере.

## Развёртывание (один раз, ~10 минут)

Нужен аккаунт Cloudflare (бесплатный) и Node.js.

### 0. Сначала — отозвать старый токен

Старый токен `8947523900:…` **скомпрометирован** (был опубликован). В Telegram у
@BotFather: `/token` → выбрать бота → получить **новый** токен. Старый после этого
перестаёт работать. Дальше используем только новый токен.

### 1. Залогиниться в Cloudflare

```bash
cd serverless/telegram-proxy
npx wrangler login
```

### 2. Записать секреты (значения вводятся в терминале, в файлы не попадают)

```bash
npx wrangler secret put TG_BOT_TOKEN   # вставить НОВЫЙ токен от @BotFather
npx wrangler secret put TG_CHAT_ID     # id группы, напр. -5287777539
```

### 3. Опубликовать воркер

```bash
npx wrangler deploy
```

Wrangler выведет адрес вида `https://adervis-lead-proxy.<аккаунт>.workers.dev`.

### 4. Подставить адрес в сайт

В [`../../js/app.js`](../../js/app.js) заменить значение `LEAD_ENDPOINT`:

```js
var LEAD_ENDPOINT = 'https://adervis-lead-proxy.<аккаунт>.workers.dev/';
```

Затем пересобрать боевые файлы (из корня сайта):

```bash
node build/minify-assets.js && node build/version-assets.js
```

и запушить.

## Проверка

После деплоя отправь тестовую заявку с сайта — сообщение должно прийти в группу.
Прямой POST с чужого домена воркер отклонит (`403 forbidden_origin`), GET вернёт `405`.

## Смена домена

Если сайт переедет на другой домен — поменяй `ALLOWED_ORIGIN` в `wrangler.toml`
и снова `npx wrangler deploy`.
